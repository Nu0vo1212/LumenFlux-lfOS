# lfOS 版本历史

## 当前状态

**最新版本：v1.0.0**（首个正式版）

lfOS 已经从「能启动」走到「可以交付」。v0.0.1 验证了启动链路，v0.0.2 做系统级性能调优，
v0.0.3 完成内核瘦身 30% 并加入场景化调优工具，v0.0.4 优化启动并扩展场景，
**v1.0.0 解决了最后的安全基线问题**：镜像里不再有硬编码凭据。

## v1.0.0 —— 第一个正式版

**发布时间**：2026-10

### 安全基线：镜像里没有可用密码

v0.0.x 全是测试配置，root 密码硬编码为 `lfos`、`PermitRootLogin yes`。v1.0.0 全部改掉：

| 项目 | v0.0.x | **v1.0.0** |
|---|---|---|
| root 密码 | `lfos`（明文可用） | **`*` 锁定** |
| SSH 密码登录 | 开启 | **默认关闭** |
| PermitRootLogin | yes | **prohibit-password** |
| 空密码账号 | 可能 | **0 个** |
| 首次启动 | 直接进 shell | **必须设置密码或配公钥** |

### 首次启动流程

镜像里 root 密码锁定、SSH 密码登录关闭。第一次启动时控制台会要求设置密码：

```
╔════════════════════════════════════════════════════════════════╗
║                    lfOS 首次启动设置                           ║
╚════════════════════════════════════════════════════════════════╝

  镜像中的 root 密码是锁定的，需要现在设置一个。
  要求：至少 8 位，不能是纯数字，不能是 root / lfos。

  新 root 密码: _
```

设置完成后自动放开 SSH 密码登录并重启 sshd。

### 三种初始化方式

```bash
# 方式一：公钥登录（推荐，适合无人值守部署）
#   把公钥写入 /root/.ssh/authorized_keys，无需密码

# 方式二：控制台交互式
lfos-set-password

# 方式三：非交互（自动化部署）
echo 'YourStrongPassword' | lfos-set-password --stdin
```

### 修了一个严重权限问题

**12 个关键程序的 setuid 位丢失**：

```
passwd   755 → 4755      su       755 → 4755
chage    755 → 4755      mount    755 → 4755
chfn     755 → 4755      umount   755 → 4755
chsh     755 → 4755      newgrp   755 → 4755
expiry   755 → 4755      newuidmap/newgidmap  755 → 4755
gpasswd  755 → 4755      ssh-agent 755 → 2755
```

后果：**普通用户改不了密码、`su` 不可用、`mount` 失败** —— 系统看着正常，实际严重不可用。

修法：新增 [`scripts/58b-fix-permissions.sh`](../scripts/58b-fix-permissions.sh)，
在 finalize 最后执行，并纳入门禁（`关键 setuid 程序在位`）。

### 实测

```
bzImage  6781 KB
ISO      163 MB
内存     121 MB
收尾门禁 10/10 通过
内核门禁 70 通过 / 0 警告 / 0 失败
```

## v0.0.4 —— 启动加速 + 场景扩到 7 种

**发布时间**：2026-10

### 启动优化

用启动参数减少虚拟机里无意义的硬件枚举：

| 阶段 | v0.0.3 | v0.0.4 | 变化 |
|---|---|---|---|
| ACPI Core | 1.078s | **0.864s** | -214ms |
| PCI host | 1.551s | **1.298s** | -253ms |
| Freeing unused | 3.187s | **3.020s** | -167ms |

加的两个**低风险**参数：
- `acpi_osi=Linux` —— 告诉 ACPI 认识 Linux，跳过 Windows 兼容性探测
- `tsc=reliable` —— 跳过 TSC 校准验证

**没有**加 `acpi=noirq` / `pci=noearly`（省更多但有设备识别失败风险），
放在单独的「极速启动」引导项里供选用。

### 场景从 5 种扩到 7 种

**`container`**：`ip_forward=1`、`neigh.gc_thresh3=16384`、`nf_conntrack_max=1048576`、
`file-max=8388608`、`pid_max=4194304`

**`ai`**：`swappiness=0`、`max_map_count=2097152`、`dirty_ratio=40`、
`overcommit_memory=1`、预读 8192KB

⚠️ 诚实说明：内核未启用 `CONFIG_USER_NS`，**不能跑 rootless 容器**；
`bridge-nf-call-iptables` 内核不支持。脚本会明确报告跳过项。

### 修正文档

- 新增本文档
- 修正此前所有 Release 说明都是「首个可启动测试版」的问题（发布脚本把 body 硬编码了）

## v0.0.3 —— 内核瘦身 + 启动优化 + 调优工具

**发布时间**：2026-10

### 内核裁剪：9669 KB → 6784 KB（降 30%）

按实测的子系统体积做针对性裁剪：

| 措施 | 依据 |
|---|---|
| 压缩 gzip → xz | 同一 vmlinux：gzip 10655KB vs xz 8402KB，省 21% |
| 整块移除 DRM | `drivers/gpu` 2483 KB；桌面方案已放弃 |
| 移除 USB 存储/HID | 服务器用虚拟磁盘，不接 USB 外设 |
| `LOG_BUF_SHIFT` 18→16 | printk 缓冲 256KB → 64KB |
| 移除冷门协议/文件系统/加密算法 | ATM/X25/NFC、NTFS/VFAT/NFS、CAST/TWOFISH 等 |

顺带清理了配置片段里 **7 处符号冲突**。

### 启动优化

内核到 init：2.97s → **2.73s**

### `lfos-tune.sh` 场景化调优

5 个场景：`web` / `database` / `file` / `minimal` / `balanced`

| 参数 | balanced | web | database | minimal |
|---|---|---|---|---|
| `somaxconn` | 8192 | 16384 | — | 512 |
| `nf_conntrack_max` | 262144 | 524288 | — | 16384 |
| `swappiness` | 10 | — | 1 | 30 |
| `max_map_count` | 262144 | — | 1048576 | — |
| 磁盘调度器 | none | none | mq-deadline | none |

### 修复

**`PATH` 缺 `/usr/local/{bin,sbin}`** —— `harden.sh`、`lfos-tune` 装了却 `not found`。
根因是非交互 SSH 不读 `/etc/profile`，用 `sshd_config` 的 `SetEnv PATH=` 解决。

## v0.0.2 —— 性能调优

**发布时间**：2026-10

### 网络

| 参数 | 变化 |
|---|---|
| `somaxconn` | 4096 → 8192 |
| `netdev_max_backlog` | 8192 → 16384 |
| `netdev_budget` | 300 → 600 |
| `tcp_fastopen` | 1 → 3 |
| `nf_conntrack_max` | 65536 → 262144 |
| `fs.file-max` | 默认 → 2097152 |

### 内存与磁盘

- `dirty_ratio` 15 → 20
- 磁盘调度器 → **none**
- 根分区 → **noatime**

### 修复

1. **init 硬编码只加载一个 sysctl 文件** —— 新增配置从未被读取
2. **没有 udev** —— `/etc/udev/rules.d/` 的规则永不执行
3. **`rootflags=noatime` 无效** —— rootfs 由 initramfs 自己挂载

### 一个有意思的发现

`vm.min_free_kbytes` 动态算出 5703KB，启动后却是 45056KB：

```
khugepaged: raising min_free_kbytes from 5703 to 45056
            to help transparent hugepage allocations
```

这是**开启透明大页的固定代价**，不是配置错误。

## v0.0.1 —— 第一次能启动

**发布时间**：2026-10

首次跑通完整启动链路：自建工具链 → 自编译内核 → 自研 init → 交互 shell。

### 内容

- 自编译内核 6.15.4-lfos
- 自研 init（bash 脚本，9 步，**无 systemd**）
- SSH、**ufw**（命令与 Ubuntu 一致）、apt/dpkg、CA 证书 150 张

### 这一版暴露的问题（后续版本已修）

- 「su 归属冲突」导致 dpkg 事务中断，出现「数据库标记已装、文件未落地」
- 992 个文件属主错误（uid 1000 泄漏），含 11 个 setuid 程序 —— 提权漏洞
- `shadow` 组缺失，gid 42 被 `_apt` 占用
- init 早期 `/tmp` 不存在，导致防火墙与 sshd 启动失败且看不到原因
- ufw 配置含非 ASCII 字符会让 ufw 崩溃
- kconfig 对不存在的符号静默忽略（`CONFIG_NETFILTER_XT_TARGET_REJECT` 等写错了名字）

## 已知限制（v1.0.0）

- **只在 VirtualBox 中验证**，未上真实硬件
- **无图形界面**：VirtualBox 下 X 栈五条路线实测全部不通（vboxvideo 内核 Oops、
  vmwgfx unsupported hypervisor、vesafb 只读、uvesafb VBE 失败、vesa 探测不到设备），
  桌面方案已放弃并清理
- **容器**：内核未启用 `CONFIG_USER_NS`，不能跑 rootless 容器
- **GPU**：不含 NVIDIA 驱动
- `apt` 源默认阿里云镜像（实测 0.27s，`deb.debian.org` 仅 ~19 kB/s）

## 从测试版到正式版做了什么

一句话概括：**把「能跑」变成「敢给别人用」**。

- 凭据从硬编码改成首次启动必然设置
- SSH 从「什么都能进」改成「默认只认公钥」
- 权限从「丢了 setuid 看不出来」改成「门禁强制检查」
- 体积从 9.5MB 内核降到 6.7MB
- 调优从「一堆 sysctl」变成「一句话切场景」
- 检查从「手工看」变成「64 项自动清单 + 3 道门禁」
